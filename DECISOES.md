# Decisões técnicas e trade-offs

Registro das escolhas feitas durante a construção do MVP, com o porquê e o que foi trocado.

## Plataforma e ferramentas

| Decisão                                                                                  | Motivo / trade-off                                                                                                                                                               |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Expo SDK 57** (React Native 0.86, React 19.2, TypeScript 6)                            | Era o `latest` estável no npm no dia da criação (`npm view expo dist-tags`). Todas as libs nativas instaladas com `npx expo install` para garantir compatibilidade.              |
| **Expo Router com `Tabs` (JS)** em vez de `NativeTabs`                                   | O template padrão do SDK 57 usa `NativeTabs`, mas o botão central "+ Gravar" com visual próprio e ação de modal só é trivial com o `Tabs` clássico (`tabBarButton` customizado). |
| **React Compiler desligado** (`experiments.reactCompiler: false`)                        | Menos surpresas com libs que mutam objetos nativos (expo-video). Os componentes críticos usam `memo`/`useCallback` manualmente.                                                  |
| **Nova arquitetura (sem `newArchEnabled` no app.json)**                                  | No SDK 57 ela é sempre ligada; a chave saiu do schema e o `expo-doctor` a rejeita.                                                                                               |
| **Sem `babel.config.js`**                                                                | O `babel-preset-expo` do SDK 57 já injeta o plugin do `react-native-worklets`/Reanimated 4 automaticamente.                                                                      |
| **Jest com resolver próprio** (`jest.resolver.js`)                                       | O Reanimated 4 depende do `react-native-worklets`, que nos testes precisa ignorar os arquivos `.native.js`; o resolver combina o do React Native com esse ajuste.                |
| **@testing-library/react-native 14** (API assíncrona: `await render`, `await fireEvent`) | Versão instalada pelo `expo install`; os testes seguem a API nova.                                                                                                               |
| **Heredocs grandes no terminal quebravam** durante o desenvolvimento                     | Limite de tamanho do comando no ambiente; arquivos grandes foram escritos diretamente. Sem impacto no projeto.                                                                   |

## Camada de dados

| Decisão                                                                                                              | Motivo / trade-off                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Uma interface (`DataService`) e dois drivers** selecionados por `EXPO_PUBLIC_DATA_DRIVER`                          | Requisito do MVP. A fábrica em `src/services/data/index.ts` instancia uma vez; telas e hooks nunca importam um driver diretamente.                                                                                                                                         |
| **Mock = um único JSON no AsyncStorage** com gravação _debounced_ (150 ms) e gravação imediata em mudanças de sessão | Simples, previsível e suficiente para ~120 vídeos + interações. Um DB relacional local (SQLite) traria mais código sem ganho para a demo.                                                                                                                                  |
| **Vídeos de exemplo de `test-videos.co.uk` e MDN (CC0)** em vez do bucket de amostras do Google                      | O bucket `gtv-videos-bucket` respondeu 403 na rede de desenvolvimento; os clipes escolhidos são curtos (4–10 s, 1–2 MB) e de licença livre. **Trade-off:** o modo demo precisa de internet para os vídeos seed (os gravados pelo usuário ficam no aparelho).               |
| **120 vídeos seed = 12 clipes × 10 variações** de legenda/autor/data                                                 | Exercita a performance do feed com 100+ itens sem baixar 120 arquivos diferentes.                                                                                                                                                                                          |
| **Miniaturas seed via Lorem Picsum** (fotos aleatórias com seed fixo)                                                | Os clipes de teste não têm thumbnail pública; gerar 120 thumbnails no aparelho seria lento. As grades de perfil ficam visualmente ricas; as miniaturas não correspondem ao conteúdo do clipe. Vídeos gravados pelo usuário geram thumbnail real (`expo-video-thumbnails`). |
| **Visitante já entra com onboarding concluído e seguindo 2 perfis**                                                  | Demo em 1 toque: a aba "Seguindo" já tem conteúdo. Contas criadas por e-mail passam pelo onboarding normal.                                                                                                                                                                |
| **Respostas em 1 nível**: responder uma resposta anexa ao comentário raiz                                            | Requisito ("respostas em 1 nível") e evita threads infinitas.                                                                                                                                                                                                              |
| **Bloquear** esconde conteúdo nos dois sentidos e desfaz "seguir"                                                    | Comportamento esperado pelas lojas; implementado nos dois drivers.                                                                                                                                                                                                         |
| **Supabase: paginação por cursor em `criado_em`** (keyset)                                                           | Estável com inserções novas, diferente de offset.                                                                                                                                                                                                                          |
| **`hashtags_norm` (array minúsculo) + índice GIN**                                                                   | Busca por hashtag sem `ILIKE` em texto; mantido por trigger.                                                                                                                                                                                                               |
| **Contadores e notificações via triggers** no Postgres                                                               | Consistência sem round-trips extras do app; `security definer` para passar pelo RLS.                                                                                                                                                                                       |
| **Visitante no Supabase = anonymous sign-in**                                                                        | Recurso nativo do Supabase Auth; o perfil é criado pelo mesmo trigger. Precisa ser ligado no painel (documentado).                                                                                                                                                         |
| **Upload com `expo-file-system` `UploadTask`** direto na REST do Storage                                             | O `supabase-js` não expõe progresso; o `UploadTask` dá progresso real e funciona com arquivos grandes sem carregar tudo na memória.                                                                                                                                        |
| **Polyfill de `structuredClone`** no cliente Supabase                                                                | O Hermes pode não ter a função, usada pelo supabase-js. Guardado por `typeof`.                                                                                                                                                                                             |
| **Denúncias ficam na tabela `reports`** sem painel próprio                                                           | Moderação manual pelo Table Editor é suficiente para o MVP (ver ROADMAP).                                                                                                                                                                                                  |

## Feed e player

| Decisão                                                                                                            | Motivo / trade-off                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| **FlashList 2 com `pagingEnabled`** e altura do item = altura medida do container                                  | Snap exato por tela sem depender de `Dimensions` (a barra de abas reduz a área útil).                                      |
| **Players montados apenas para o item ativo e seus vizinhos (±1)**                                                 | Limita a 3 players nativos simultâneos; o vizinho fica pausado e pré-carregado. Os demais itens mostram só um fundo preto. |
| **`itemVisiblePercentThreshold: 60`** define o item ativo                                                          | Evita "ping-pong" no meio do gesto.                                                                                        |
| **`contentFit` por orientação** (`cover` para vídeos em pé, `contain` para paisagem)                               | Os clipes seed são 16:9; vídeos gravados no celular são 9:16.                                                              |
| **Posts de foto = imagem + barra de progresso de 5 s em loop**, sem avançar sozinho                                | Avançar automaticamente atrapalha quem está lendo a legenda; a barra comunica a "duração".                                 |
| **Duplo toque via `Gesture.Exclusive(tapDuplo, tapSimples)`**                                                      | Sem o `Exclusive`, o toque simples (mudo) dispararia antes do duplo.                                                       |
| **Visualização registrada após 2 s** com o item ativo                                                              | Evita contar passagens rápidas.                                                                                            |
| **Atualização otimista** de curtir/salvar em todos os caches (feeds infinitos, listas, vídeo único) com _rollback_ | A UI responde na hora e fica consistente entre feed, perfil e explorar.                                                    |
| **Regra `react-hooks/immutability` desligada em 2 linhas** do `PlayerDeVideo`                                      | O player do `expo-video` é um objeto nativo compartilhado; mutá-lo (`muted`, `currentTime`) é o uso documentado da lib.    |

## Câmera e publicação

| Decisão                                                                                                                                        | Motivo / trade-off                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Duração medida pelo cronômetro** durante a gravação                                                                                          | `recordAsync` não retorna duração; `maxDuration: 60` garante o limite no nativo também.          |
| **Thumbnail gerada no aparelho** (`expo-video-thumbnails`) antes de publicar                                                                   | Funciona nos dois drivers; no Supabase evita processamento no servidor.                          |
| **"Salvar na galeria" opcional, ligado por padrão para gravações da câmera**                                                                   | Usa `expo-media-library` de forma útil sem forçar permissão para itens que já vieram da galeria. |
| **Progresso do upload:** real no Supabase (bytes enviados); no mock são etapas reais (copiar arquivo → thumbnail → salvar) com pequenas pausas | Demonstra a barra sem inventar números.                                                          |

## Lives

| Decisão                                                                                             | Motivo / trade-off                                                                                                                                                                                                                 |
| --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`@livekit/react-native` 2.12** (não a 3.0)                                                        | É a versão exigida pelo peer do `@livekit/react-native-expo-plugin` 1.0.2 instalado junto.                                                                                                                                         |
| **`@livekit/react-native-webrtc` fixado em `144.1.2`** (versão exata, sem `^`)                      | A 144.2.0 migrou para o WebRTC Android _prefixado_ (`livekit.org.webrtc`), que só a 3.0 do `@livekit/react-native` usa; com a 2.12 o Gradle falha em `compileReleaseKotlin`. Ao subir para a 3.0, subir o webrtc junto.            |
| **`require()` guardado por `NativeModules.LivekitReactNativeModule && NativeModules.WebRTCModule`** | Importar o pacote estaticamente quebra no Expo Go (o `react-native-webrtc` toca módulos nativos ao carregar). O `require` só executa quando os módulos existem; o Metro ainda empacota o código (bundle +3 MB), o que é aceitável. |
| **Modo simulado = câmera local (anfitrião) / capa animada (espectador) + chat real**                | Requisito: a demo nunca quebra no Expo Go, com aviso discreto e motivo.                                                                                                                                                            |
| **Tokens do LiveKit por Supabase Edge Function**                                                    | A API Secret não pode ir para o app; a função também garante que só o anfitrião publica.                                                                                                                                           |
| **Chat no mock com "bots"** (mensagens e reações a cada 3,5 s, contador de espectadores oscilando)  | Deixa a demonstração viva sem segundo celular. Desligável (`botsNaLive: false`, usado nos testes).                                                                                                                                 |
| **Reações do próprio usuário aparecem na hora e não são duplicadas** quando voltam do servidor      | Filtro por `autorId` no evento de reação.                                                                                                                                                                                          |

## Camada temática

| Decisão                                                                        | Motivo / trade-off                                                                                                            |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| **`MatchService` com JSON local e datas relativas a "hoje"**                   | A demo nunca mostra jogos "velhos". A interface `MatchService` permite plugar uma API real (ver ROADMAP) sem tocar nas telas. |
| **Ranking semanal = soma de curtidas dos vídeos dos últimos 7 dias por autor** | Simples de explicar e de calcular nos dois drivers (RPC `ranking_semanal` no Supabase).                                       |
| **Reações 🔴⚫🦅🏆 só na live**                                                | Requisito: no feed permanece o coração.                                                                                       |

## Identidade visual

| Decisão                                                                                | Motivo / trade-off                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Nenhum elemento visual que lembre TikTok/Kwai**                                      | Evitar confusão de marca: sem o "+" com sombras coloridas, sem coluna lateral de ícones brancos, sem abas centralizadas no topo. As ações ficam numa barra horizontal dentro de um painel de vidro. |
| **Ícones Feather + Material via `components/ui/Icone`**                                | Uma única fonte de ícones de traço fino, distinta da família usada pelos concorrentes; trocar a família inteira é mudar um arquivo.                                                                 |
| **Paleta rubro-negra sóbria (`#C8102E` sobre `#0A0A0B`) + dourado só para conquistas** | Identidade da torcida sem escudo, uniforme ou marca registrada. A faixa `Listras` (dois tons de vermelho) é o único motivo decorativo.                                                              |
| **Tipografia do sistema com pesos 800/900, caixa alta e espaçamento nos rótulos**      | Visual esportivo/profissional sem carregar fontes externas (zero dependências novas, sem download no `expo start`).                                                                                 |
| **Cabeçalhos, chips e estados vazios padronizados (`Cabecalho`, `TituloDeSecao`)**     | Consistência entre as 20+ telas com menos código duplicado.                                                                                                                                         |

## Testes

| Decisão                                                                                                                 | Motivo / trade-off                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Cobertura medida em `src/services` e `src/components`**, excluindo o driver Supabase e o carregador nativo do LiveKit | Ambos exigem backend/módulos nativos reais; o resto do código é coberto por 92 testes (76% de linhas). O driver Supabase é validado pelo roteiro manual com um projeto real. |
| **`MockDataService` com latência 0 e ids determinísticos nos testes**                                                   | Testes rápidos e estáveis; em runtime a latência de 120 ms simula rede.                                                                                                      |
| **Mocks de `expo-video`, `expo-file-system`, `expo-haptics`, `expo-router` e safe-area no `jest.setup.ts`**             | Nenhum deles funciona no Node; os mocks são pequenos e ficam num único lugar.                                                                                                |

## O que ficou fora do escopo (e por quê)

- **Transcodificação, CDN e HLS** — exigem serviço pago ou infraestrutura própria (ROADMAP).
- **Algoritmo de recomendação** — precisa de dados de uso reais; o feed é cronológico.
- **Push notifications** — exige development build/EAS e credenciais das lojas; as notificações são em tela.
- **Painel de moderação** — as denúncias ficam na tabela `reports`.
- **Curtir comentários** — a coluna `likes_count` existe no schema, mas a UI não foi priorizada.
- **API real de partidas** — todas as boas são pagas ou com limite muito baixo; ficou a interface pronta.
